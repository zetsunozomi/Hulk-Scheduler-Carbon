# 2026-09-17：AMSP 与历史负载方案的自审

这是作者助手的审查记录，不是外部评审意见。实验结论仍全部待验证。

## 判定

接受它作为**公开性能数据驱动的受控调度研究**。不接受“旧机器日志适用于任意新机器”或“归一化保证排队行为泛化”的主张。主贡献仍是有完成预算的请求决策及其相对碳排边界，日志变换不是新贡献。

## 第一轮：输入是否能直接使用？

- AMSP 固定 global batch，纯数据并行加状态分片，每节点 8 张 A800。图 12 的横轴是 8/32/128/512/1024 卡。原来的 4/8/16/32 节点不能原样套用：缺少 64/256 卡数据。
- 选择 32/128/512/1024 卡，即 4/16/64/128 节点；三个模型共同支持这四点。只取 Our Work 系列，不拼接各方法的最优点，不插值缺失规模。
- 图中 TGS 是每 GPU 每秒 tokens；必须乘总 GPU 数，再除每 update 的 tokens。1024 条序列、每条 4096 tokens，由文中两个 accumulation 设置交叉确定；“4M”不是直接当作 4,000,000。
- PDF 矢量柱形数字化记录坐标、轴、版本 hash，TGS 四舍五入到 10；它是公开输入，不是本项目的新实验，更不是源 benchmark 原始日志或测量置信区间。

## 第二轮：机器与日志的组合是否自洽？

调度器实际消费的是 (arrival, width, requested duration, occupied duration)。给定这些量、初始状态和同一调度规则，机器名称不会另行改变排队结果。这是模型的条件性边界，不是声称换硬件后这些量不变。

两份原始流分别定义资源需求场景，保留原时间顺序和 width/runtime/request 的联合结构；不逐作业混洗，不用 FLOPS 换算未知旧作业。名义模拟容量明确设为 128 个八卡节点，对应 AMSP testbed 的规模，但并不称它为任一原日志的平台容量，也不声称该 testbed 位于 Texas。Texas CI 是外加的地区情景。

旧 Start/End 之差只给后台占用时长。不得用旧 Start 创建新平台正在运行的作业；新场景从同一个声明的前缀起点空状态回放并生成 admission，每个目标 episode 深拷贝对应状态。至少 28 天不计分前缀，并检查前缀依赖。整个目标执行期间状态持续推进，不在每次 checkpoint 重置。

原平台 observed wait 不是新场景的标签，因此删除把它用于新场景“真实误差验证”的要求。原 E1 历史回放功能保留用于原平台研究，但程序拒绝把 workload_template 送进该验证入口。

## 第三轮：这是否只是给仿真换个名字？

仅改名称不够。E1 必须报告每个场景实际覆盖的需求分布、突发程度、占用率和等待尾部，并以可独立求解的小案例验证调度器。E2 在两份来源上分别展示全部方法，不以混合后的单一平均值遮掩失败。

E4 的新增成本限于一个预设预算、7B、两个来源、full 与 Rollout-MPC，复用已训练模型：分别提高后台宽度、切换 strict FCFS、降低/提高 checkpoint 开销。每个变体重新回放；不将它当作改一个系数即可完成的后处理。冻结真实小时预算、profile 工作量、预测器、RL、参考量与 CI。报告成本和 miss，不能挑其中成功的变体。

这检查结论对**所声明环境族**的依赖。若对比在一个变体失效，应报告适用范围；不能通过调参或扩大未报告的搜索来维持泛化主张。无需另加 zero-shot 跨集群学习主张，它回答的是另一个问题，也会引入额外训练/选模协议。

## 第四轮：公开吞吐是否等于可运行的弹性训练系统？

不等于。AMSP 图 12 没有报告我们需要的完整 checkpoint 保存/恢复成本，更没有验证本系统跨规模重启。主方案设每 chunk 共 600 秒 allocated overhead，初始化/恢复与保存各 300 秒；60/1800 秒是低/高情景，不称为实测范围。仅模拟优化器更新数和工作守恒，不声称已实现 AMSP migration、最终模型质量或真实端到端部署。

## 提交前仍必须满足的证据

1. 固定/混合/规划与 RL 的完整结果，包含失败、censoring 和 miss。
2. 等待预测器在独立模拟 probes 上的尾部与排序表现。
3. 队列规则/需求/开销改变时的适用范围，以及既有功率敏感性。
4. source 与 config 固定在运行前。作者确认旧数据做过 train/validation 二分，因此本轮使用披露过往使用的回顾性三段 benchmark；不声称全新未触碰 holdout，也不要求新日志作为启动前提。

此方案在逻辑上成立；它仍是一项受控模拟研究，而不是任意硬件上的线上效果验证。能否支撑顶会贡献最终取决于对强规划基线的实际增量和机制证据，不能用自审代替实验。

## 第五轮：用户层能否合理依赖等待预测？

当前回答是不应把准确预测当作前提。旧设计给 RL 输入 wait mean/p90 和 predicted-window exposure，仅把奖励改成 realized outcome 不能证明 RL 不依赖这些输入；残差分布也不等于对模型失配稳健。

修正主策略为显式等待预测器之外的反馈控制：读公开 queue history、工作/剩余预算、action execution descriptors 和 causal CI 时间序列。每次真实完成更新下一次的预算；只在 checkpoint 边界选请求，不取消排队任务、不操纵 Slurm、不声称 per-job SLA。

审稿反问仍成立：“critic 不也是预测未来吗？”是，学习的 continuation cost 仍依赖训练环境；我们删除的是单独 admission 预测及其校准要求，不声称完全无预测/任意分布稳健。E4 的 frozen width/FCFS 检查这个剩余依赖。

E3 以 Predictor-advised 对照替换 Current-CI，消融组数不加；辅助训练必须匹配主策略完整预算网格与总交互数，不能单预算重训后把训练条件的差异算作预测器效果。强固定/混合基线保留，防止单凭弱 MPC 得出 RL 优势。若只有 advised 胜出，主结论必须收缩。E1 照常完成，其差结果也是有效的诊断，不设必须预测准的门槛。所有性能结果仍待测。

## 第六轮：只保留自洽的 user-level slider 主线

决策：不保留原“等待估计预训练 + 决策器”的两阶段结构。核心是一个 budget-conditioned feedback policy：只控制下一次请求节点数，Slurm 控制 admission；slider 选择 D，端到端完整实际回报训练。可以重新增配，不能在运行中 resize。

逐条审查：
1. 理想 feedback 策略类包含预先排序列，后者包含 fixed/每任务 fixed mixture；最优可达曲线有改善空间，但不能推导 PPO 一定赢或每个档位都赢。
2. 固定 CI/零队列/零开销的 null case 排除了“规模混合天然更好”的错误论证。人工构造已精确核验两条不同动态点可在 T/C 上同时胜 fixed4/8；它不是论文实验。
3. 赢 fixed 可能只说明预先混合有用，因此 E3 以 Precommitted-RL 替换上轮 advised 组。同架构/同完整预算/同到达/同 seed/同总交互，全部动作在首次提交前采样并存档，不读后来反馈；实际执行仍全部排队。
4. 移除主方法章节的预测器训练段，仅在评估中解释强规划基线的模型。E1 不废弃，因为场景尾部与 planner 输入仍需审计；其准确率不是主策略门槛。
5. slider 映射物理预算，所有冻结档位和失败点都报告；未评估档位不插值宣称成功。现有 48h chunk 与 AMSP 高规模可能产生大量单 chunk，须报告而不能强制多次切换制造动态优势。

此处停止继续增加学习模块。剩余判据就是正式固定/混合/规划/预先学习序列对比及已有环境压力测试；不再要求新的 Qwen、整节点功率或 Slurm 改造。
